# Плагин развёртывания приложений в один клик（kore-plugin-app-deploy）

## Обзор

Плагин обеспечивает реальное развёртывание приложений в один клик: 9 встроенных шаблонов (Node.js / Python / PHP / MySQL+phpMyAdmin / Uptime Kuma) запускают контейнеры через docker CLI хоста (фиксированный argv, без shell). Записи хранятся в `<state>/deployments.json` (0600); `list` сопоставляется с `docker ps` для показа реального состояния и сводки по ресурсам. Развёрнутые приложения можно останавливать, запускать и просматривать их логи; `remove` требует явного `confirm=true` и удаляет только контейнеры, созданные этим плагином.

## Поверхность протокола

Протокол `kore.plugin.v1`, `lifecycle=lazy`, `depth_level=production`, возможность `system:admin`. Одиннадцать бизнес-методов, домен должен совпадать с id плагина `app-deploy`: развёртывание по шаблону `templates` / `deploy` / `list` / `remove`, пользовательский артефакт `upload` / `deployFromArtifact` / `upgrade` / `jobs`, управление после развёртывания `stop` / `start` / `logs`. stdout handshake зарезервирован для кадров протокола; логи всегда идут в stderr.

## Основные возможности

Шаблоны — локальные константы, без сети и загрузок: начиная с 0.4.0 `ports[]` содержит `suggested_host_port`, который ищет вверх от порта по умолчанию первый свободный и привязывается только к `127.0.0.1`. Артефакт пользователя не более 32 МиБ; каждый элемент отклоняет абсолютные пути, `..`, буквы дисков, обратные слеши и ссылки; `upgrade` сначала снимает снимок старого каталога, а при ошибке автоматически откатывается. Уровень управления `stop` / `start` / `logs` — дополнительная возможность, работающая только с именами контейнеров из записей развёртывания; при недоступности возвращается `E_UNSUPPORTED`.

## Граница безопасности

Список разрешённых шаблонов ограничивает образы константами исходного кода, а `deploy` принимает только id шаблона; имена должны начинаться с `kore-app-` и соответствовать `^[a-z][a-z0-9-]{0,30}$`; принимаются только объявленные шаблоном переменные окружения, настоящие секреты передаются через `--env-file` с правами 0600 и никогда не попадают в argv; удаление требует `confirm:true`, записи о развёртывании и проверки полного ID контейнера, чужие контейнеры не затрагиваются; каждый контейнер имеет `--memory` и равный `--memory-swap` для защиты от OOM; bind-монты остаются внутри `<state>/volumes/`.

## Сборка и проверка

Ежедневная проверка — локальный `make check` (gofmt → go vet → go test -timeout 200s); перед выпуском запустите `make dist` дважды и подтвердите совпадение sha256 (архив с `--sort=name --mtime=@0 --owner=0 --group=0 --numeric-owner` и `gzip -9n`). Реальный docker E2E по умолчанию пропускается; после включения через `make e2e` отсутствие docker приводит к ошибке, а не к пропуску. Каталог состояния задаётся `KORE_APP_DEPLOY_STATE`, по умолчанию `<root>/state`; на не-Linux платформах возвращается `E_UNSUPPORTED`.
